# 规则合并脚本

使用 Node.js 24 运行：`node Script/merge-rules.js`。
默认读取脚本所在仓库的 `Rule/merge.yaml`，并写入同一个 `Rule` 目录；默认路径不依赖启动时的工作目录。
从其他目录启动时，请提供脚本的绝对路径。通过 `main({ configFile, outputDir })` 显式传入的相对路径仍相对于启动目录。

## 配置格式

脚本无第三方依赖，只支持以下 YAML 子集，不是通用 YAML 解析器：

```yaml
proxy:
  url:
    - https://example.com/rules.txt
  rules:
    add:
      - DOMAIN,example.com
    remove:
      - DOMAIN,unwanted.com
```

- 分类名对应 `<分类名>.txt`，允许英文字母、数字、点、下划线、加号和连字符；不能以点结尾，不能使用 Windows 保留文件名，分类名不能仅大小写不同。
- 每级缩进使用两个空格，不能使用制表符。`url`、`rules`、`add`、`remove` 可省略，空列表写为 `[]`。
- URL 及规则使用不带引号的单行文本。只支持 HTTP/HTTPS URL。
- 注释独占一行，以 `#` 开头。不支持行尾注释、引号字符串、多行标量、锚点、别名和内联集合；不支持的写法会报告行号。
- `remove` 按去除首尾空白后的完整规则精确匹配，区分大小写，不支持通配符；在下载和新增之后执行，所以删除优先。

## 生成与清理

- 下载结果和新增规则去重、排序后写入文件；忽略空行及以 `#` 开头的注释行。
- 任一来源下载失败时保留该分类旧文件，继续处理其他分类，并返回失败状态。
- 单个成功下载的空来源仍允许与其他来源合并。合并新增规则后、执行删除前为空时，保留旧文件。
- 无下载来源且无新增规则的分类跳过生成并保留旧文件，单独配置 `remove` 不会修改旧文件。
- `remove` 删除全部规则时，输出只含更新时间的文件。
- 规则集合未变时直接比较集合，跳过排序和写入，保留原文件及更新时间；更新使用临时文件再重命名。
- 输出文件名与配置文件路径冲突时，在下载、生成和清理前报错，避免覆盖配置。
- 配置解析成功后，生成阶段结束时清理目录直属的多余 `.txt` 文件（扩展名不区分大小写）。Windows 文件名比较忽略大小写，Linux 精确匹配；Linux 上仅更改分类名大小写也会清理旧名称文件。
- 配置中保留的分类即使生成失败或跳过，也在清理保留列表中。配置文件本身、其他类型文件、子目录及符号链接不参与清理。
- 部分分类失败时仍执行过期文件清理。配置解析失败时不生成、不清理。清理遇到文件操作错误会终止并报错，已完成的操作不会回滚。
- 汇总包含 `updated`、`unchanged`、`skipped`、`failed` 和 `deleted`。
